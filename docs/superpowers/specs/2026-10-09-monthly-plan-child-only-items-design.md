# 課程月計畫：個別項目（只給一位幼兒的課程）設計

## 背景

課程月計畫裡，一天的項目（指標、活動名稱、指標內容）是同階段幼兒**共用**的（同一筆 PlanSlot），只有「未達成」「請假／其他活動代替」是每位幼兒各自的（ChildItemOverride）。

實際需求：幼兒某天請假，老師會在**另一天替他補課**，補課是原課程之外**多上一堂**。現在在某天新增項目，同階段的所有幼兒都會出現，做不到「只給這位幼兒」。偶爾會有兩位同階段幼兒同天請假、同天補課，希望不用重新選一次指標、打一次活動名稱。

請假本身不需要改：勾「請假」原本就只影響那位幼兒。

## 用詞（畫面上統一使用）

| 用途 | 文字 |
|---|---|
| 同階段都看得到的項目 | 共用項目 |
| 只屬於一位幼兒的項目 | 個別項目 |
| 新增表單的欄位名稱 | 適用幼兒 |
| 兩個選項 | 同階段共用（預設）／僅限○○（○○＝目前這格的幼兒名字） |
| 複製給其他幼兒的那一行 | 同時新增給： |
| 月曆格子與編輯面板上的標籤 | 個別 |
| 刪除個別項目的確認 | 確定要刪除○○的個別項目「活動名稱」嗎？此操作無法復原。 |
| 刪除共用項目的確認 | 不變（同階段的 N 位幼兒都會一起刪除…） |

## 資料

PlanSlotItem 多一個**選填**欄位 `childId`：

- **沒有這個欄位**（不是 `null`，是整個不存在）＝共用項目，跟現在完全一樣。舊資料不用轉換。
- 有 `childId` ＝ 個別項目，仍掛在同一個 PlanSlot（同 tier/week/weekday）底下，只有那位幼兒看得到。

刻意用「欄位不存在」而不是 `childId: null`：同步（`syncStores.js` 的 `serializeRecord`／`deserializeRecord`）只改寫記錄裡實際存在的參照欄位，`null` 的 `childId` 經過 `deserializeRecord` 會因為對不到幼兒而被當成「參照還沒到」整筆略過。

**一個個別項目只屬於一位幼兒**。「同時新增給」是新增時各建一份獨立的副本，不是多人共用一份 — 改或刪小明的那份永遠不會動到小華的。代價是兩份要修正時要各改一次，補課項目加了通常不再改，可以接受。

### 會讀寫 PlanSlotItem 的地方

| 位置 | 改動 |
|---|---|
| `monthlyPlanDb.js` `addPlanSlotItem` | 接受 `childId`，有值才寫進記錄 |
| `monthlyPlanDb.js` | 新增 `deleteChildOnlyItemsForChild(planId, childId)`：刪掉這位幼兒在此計畫的所有個別項目（走 `deletePlanSlotItem`，順便清掉該項目的 override） |
| `monthlyPlanEditorView.js` 管理幼兒「儲存」 | 移出計畫的幼兒，除了清 override，也呼叫 `deleteChildOnlyItemsForChild` |
| `db.js` `deleteChild` | 同上 |
| `backup.js` 匯入 | `childId` 透過 `childIdMap` 對應；對不到（幼兒不在備份裡）就整筆不匯入，跟 override 的 dead-child 處理一樣。匯出本來就整筆輸出，自然帶上 `childId` |
| `syncStores.js` planSlotItems | `refs` 加 `childId: CHILD_REF`；`naturalKey` 在有 `childId` 時附加上去（`slotId|activityName|childId`），沒有時維持原本的 `slotId|activityName`，舊資料比對結果不變。不加的話，兩位幼兒同天同名的補課項目會在第一次登入比對時被誤認成同一筆 |
| `monthlyPlanEditorView.js` 月曆格子、編輯面板 | 只顯示「共用項目＋這位幼兒的個別項目」 |
| `monthlyPlanDocxExport.js` | 每位幼兒的表格只輸出「共用項目＋他自己的個別項目」，個別項目跟一般項目長得一樣，不標「個別」 |

篩選規則只有一條，寫成一個小函式共用給畫面和匯出：`item.childId === undefined || item.childId === child.id`。

幼兒階段在月計畫建立後沒有任何畫面可以修改（只在建立／匯入時決定），所以不處理「改階段」。

## 畫面

只用 App 現有元件，不新增樣式類型。

### 新增項目表單

「適用幼兒」放在表單最上面：

```
適用幼兒
 (同階段共用) (僅限小明)          ← .tier-switch 膠囊按鈕，單選

同時新增給：                      ← 只在選「僅限小明」時出現
 [□ 小華] [□ 小美]                ← .panel-form__checkbox 膠囊勾選，預設不勾

指標所屬年齡層 / 指標 / 活動名稱 / 指標內容
[新增項目]
```

- 「同時新增給」只列出**這個計畫裡同階段的其他幼兒**；沒有其他同階段幼兒就整行不顯示。
- 選回「同階段共用」時這一行收起，勾選一併清掉（避免看不到卻還勾著）。
- 新增成功後表單照現在的方式整個重畫，「適用幼兒」回到預設「同階段共用」。

### 標示

- 月曆格子：個別項目文字前面加「個別」標籤，樣式沿用 `.indicator-block__code` 的灰底小標籤（月曆格子字較小，標籤字級跟著格子縮小）。
- 編輯面板的項目卡：標題的指標代碼前加同樣的「個別」標籤。

### 編輯／刪除

- 編輯個別項目只改它自己（它本來就只屬於一位幼兒）。
- 刪除個別項目用上表的確認文字，不顯示「同階段 N 位都會一起刪除」。
- 新增之後不能改適用範圍；要改就刪掉重新新增。

### 電腦版／手機版

沿用編輯面板現有三種排版，不需另外處理：寬螢幕（≥1280px）面板在右側欄；641–1279px 是彈出視窗；手機（≤640px）全寬彈出視窗。膠囊用 `flex-wrap` 自動換行，手機上也好點。月曆格子只多一個小標籤，格寬不變。

## 操作說明

依專案規定，「課程月計畫」章節新增一段示範「幫一位幼兒補課」（電腦版／手機版都有）：打開補課那天 → 適用幼兒選「僅限王小明」→ 按「新增項目」→ 只有王小明的格子出現帶「個別」標籤的項目。「安排一天的活動」的說明文字補一句：要只給一位幼兒，見「幫一位幼兒補課」。

## 測試

- `monthlyPlanDb`：`addPlanSlotItem` 不傳 `childId` 時記錄沒有這個欄位；`deleteChildOnlyItemsForChild` 只刪該幼兒的個別項目和其 override，不動共用項目和別人的個別項目。
- 編輯畫面：選「僅限○○」新增後，只有該幼兒的格子有項目並帶「個別」標籤；勾「同時新增給」另一位，兩人各有一份，刪其中一份另一份還在；刪除確認文字；選回「同階段共用」時勾選被清掉；沒有其他同階段幼兒時不顯示「同時新增給」；移出計畫時個別項目被刪除。
- 匯出：個別項目只出現在所屬幼兒的表格。
- 備份：匯出再匯入後 `childId` 對應到新的幼兒 id；幼兒不在備份裡的個別項目不匯入。
- 同步：`childId` 經 serialize/deserialize 轉換；沒有 `childId` 的記錄不多出這個欄位；兩份同名個別項目的 naturalKey 不同。
- 介面：`npm run build` 後用 Playwright 開 `dist/TableC.html`，在電腦寬度與手機寬度各走一次「僅限＋同時新增給」流程並截圖檢查。

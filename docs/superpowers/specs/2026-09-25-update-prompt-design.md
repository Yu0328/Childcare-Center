# 新版本改成「提示更新」— 設計

## 問題

網頁版（GitHub Pages）重新部署後，瀏覽器在背景裝好新版的離線程式（Service Worker），舊的程式會立刻交棒，頁面接著自動重新整理。老師如果正在填一個還沒按儲存的表單，打到一半的內容會不見。第一次打開網站時也會莫名其妙重新整理一次。

## 做法

- `sw.js` 安裝後不再自己 `skipWaiting()`，而是等頁面傳來 `'SKIP_WAITING'` 訊息才交棒。
- 頁面發現有新版在等待（載入時已經有 `registration.waiting`，或之後的 `updatefound` 裝好了），而且目前已經有舊版在服務時，在畫面底部顯示提示條：「有新版本」＋「更新」按鈕。第一次安裝（沒有舊版）不顯示。
- 按「更新」才傳訊息給新版，新版接手（`controllerchange`）後才重新整理。沒按更新就不會自動重新整理。
- 不按也沒關係：所有分頁都關掉後，下次打開就是新版。而且網頁本身一向是先從網路抓最新的，所以提示條只是把背景的離線程式也換成新版。

邏輯放在 `src/pwa/updatePrompt.js`，從 `webEntry.js` 匯出，讓 `build-web.mjs` 呼叫。離線單檔版（`build.mjs`）沒有 Service Worker，不受影響。

## 過渡

已經在用的舊版頁面，還是跑舊的「交棒就重新整理」程式，所以這次部署本身仍可能自動重新整理一次；之後的部署就會改用提示。

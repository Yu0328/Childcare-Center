# 網頁版無感自動更新 — 設計

## 問題

2026-09-25 起（`2026-09-25-update-prompt-design.md`），新版要等老師按畫面上的「有新版本［更新］」才換上，避免頁面自己重新整理、吃掉填到一半的內容。但這需要老師注意到提示條並按下去；而且 App 只在打開網頁時才檢查新版，手機把 App 放在背景再切回來（不是重新打開）時根本不檢查，可能好幾天都停在舊版。

希望改成：老師**不知不覺**就換成新版，而且**絕不會**在填表時突然跳回首頁或吃掉內容。

## 關鍵限制

- 換版一定要重新載入頁面，而 App 沒有記住目前畫面，重新載入**一定回到首頁**。所以只要老師不在首頁，就絕對不換版。
- 用 Google 登入的老師，重新載入後會再看到「使用 Google 登入／訪客」選擇畫面（`wireSyncControls.js` 刻意不自動登入，避免突然跳出 Google 視窗）。Google 登入是預設用法，所以要把登入狀態帶過這次重新載入，才算無感。
- Google 的通行證（access token）刻意只放在記憶體、從不存檔（`googleAuth.js` 開頭註解）——裝置沒有鎖，存在硬碟上的東西任何拿到裝置的人都讀得到。交接方式必須守住這點。

## 做法

### 1. 更早發現新版

除了打開網頁時，老師每次切回 App（畫面回到前景）也請瀏覽器檢查一次新版（`registration.update()`），開著不關時每 30 分鐘再檢查一次。新版照舊在背景下載好、處於等待狀態，老師看不到。

### 2. 安全時機才換版

新版已在等待時，**全部**成立才換：

- 停在**首頁**（`showReportTypeSelect` 畫的那個畫面）。首頁沒有輸入欄位，重新載入後也是首頁，畫面看起來不變。
- `hasUnsavedInput(document.body)` 為假（雙重保險；也涵蓋首頁上若有開著的彈出視窗）。
- 沒有正在同步，也沒有排隊等著同步（同步引擎的進行中工作或延遲計時器）。
- 不在資料衝突畫面、不在登入選擇畫面（這兩個都不是首頁，第一條已擋掉，仍明列）。登入選擇畫面和首頁共用樣式，所以首頁另有專屬標記 `data-screen="home"`。
- 不是 App 自己打開的東西讓頁面跑到背景：Google 登入視窗開著時（`isSigningIn`，算進 `isBusy`），或剛點了選檔案（`input[type=file]`；選好／取消，或回到前景 1 秒後才解除）。手機上這兩種都會讓頁面「離開」，但老師其實還在操作。

觸發時間點：

- **老師離開 App 時**（`visibilitychange` 變成 hidden）：條件成立就換。老師回來看到的是同一個首頁，已是新版。
- **老師回來的那一刻**（變成 visible）：有些手機一離開就凍結網頁，前一步可能沒跑完。回來時若新版仍在等、條件成立，立刻換——首頁閃一下，不掉資料。

條件一直不成立（例如整天都在填表）就不換；下次重新打開 App 本來就是新版（網頁一向先從網路抓最新的）。

### 3. 重新載入前再檢查一次

換版是「通知新版接手 → 新版接手（`controllerchange`）→ 重新載入」，中間約零點幾秒，老師可能剛好點進表單。所以在 `controllerchange` 真正要重新載入的前一刻，**重新檢查第 2 節的條件**：

- 仍成立 → 重新載入。
- 不成立 → 這次取消，不重新載入。老師繼續用畫面上的舊程式，填表、儲存都正常。記下「新版已接手但頁面還沒重新載入」，下一個安全時機（離開或回來時條件成立）直接重新載入，不用再等新版。

另一個分頁換版造成的 `controllerchange`，也一樣只在這個分頁條件成立時才重新載入（之前是一律不重新載入）。

### 4. Google 登入接續

- 自動換版、真正重新載入的前一刻：如果是 Google 模式而且通行證還有效（距離過期超過 5 分鐘），把通行證和到期時間寫進 `sessionStorage`（只屬於這個分頁，關掉分頁就沒了）。
- 新頁面建立 `createGoogleAuth` 時：讀出來、**立刻刪除**，還有效就當成已登入。通行證在暫存區裡只存在重新載入的那一瞬間。
- `gate`：Google 模式、已有有效通行證時，略過選擇畫面，直接開始同步並進入 App。
- 通行證已過期或快過期：不交接。重新載入後看到選擇畫面——此時上方本來就會顯示「登入已失效」，老師本來就要重新登入，不算多一步。
- 訪客模式：沒有登入問題，直接換版。

只有自動換版會寫這個暫存；一般重新整理、重新打開仍維持原本「不自動登入、出現選擇畫面」的行為。

### 5. 移除提示條與說明

- 拿掉「有新版本［更新］」提示條（`updatePrompt.js` 的 `offer()`、`styles.css` 的 `.update-banner`）。
- 拿掉操作說明「常見問題」裡「出現『有新版本』？先把正在填的內容存好，再按『更新』。」（`src/ui/helpContent.js`）。
- 這次的無感更新**不放進**操作說明。

## 範圍

- 只影響網頁版（`build-web.mjs`）。離線單檔版 `TableC.html` 沒有 Service Worker，不受影響。
- `sw.js` 不變：仍是等 `'SKIP_WAITING'` 訊息才交棒，只是改由程式在安全時機自動送出。
- 「在首頁」的判斷由 `mountApp` 提供（例如首頁畫面時在容器上標記），`updatePrompt.js` 只讀這個判斷，不認得各個畫面。

## 測試

- `tests/updatePrompt.test.js` 改寫：
  - 首頁 + 離開 App → 送出 `SKIP_WAITING`，接手後重新載入。
  - 在表單裡 → 不送出。有未儲存內容 → 不送出。同步中或排隊同步 → 不送出。
  - 回到前景時新版仍在等、條件成立 → 換版。
  - 送出後、接手前離開首頁 → 接手時不重新載入；之後回到首頁並離開 → 重新載入。
  - 第一次安裝（沒有舊版）不會觸發重新載入。
  - 回到前景與每 30 分鐘會呼叫 `registration.update()`。
  - 不再出現提示條。
- `googleAuth` 測試：有效通行證會交接且讀出後立即刪除；快過期／過期不交接；沒有交接資料時行為不變。
- `wireSyncControls` 測試：有交接到的通行證時略過選擇畫面並開始同步；沒有時照舊出現選擇畫面。
- `npm run build:web` 後用 Playwright 跑實際網頁版：部署舊版 → 換成新版 → 模擬離開 App → 確認換上新版且仍在首頁；在表單中打字時換新版 → 確認不重新載入、內容還在。

# 適性紀錄(家長版) — 設計文件

日期：2026-08-08

## 背景與問題

托育人員除了「嬰幼兒發展評量紀錄表（C表 / 適性總表，已於第一階段數位化）」以外，每月還要為每位幼兒手寫一份「每月課程計畫表」＋「每月嬰幼兒適性發展紀錄表」＋「點滴分享」照片集，合稱「適性紀錄(家長版)」，用於提供家長參考。目前這份文件完全在 Word 中手工排版、手動插入照片，格式複雜、耗時。

本文件涵蓋將「適性紀錄(家長版)」數位化，做法與第一階段（C表數位化）一致：單一 HTML 檔案、IndexedDB 儲存、docx.js 產生格式一致的 Word 匯出檔。

參考範例（真實幼兒的姓名與紀錄內容，不可提交進版本控制，檔案已列在 `.gitignore`）：
- 一份「適性紀錄(家長版)」空白範本結構的 .docx 樣本
- 一份實際填寫完成、含照片的「適性紀錄(家長版)」.pdf 成果樣本

## 範圍

本文件涵蓋「適性紀錄(家長版)」的建立、填寫、儲存、匯出、舊檔匯入。C表（適性總表）功能已完成，不在本次變更範圍內，但共用同一份幼兒名單與月齡階段邏輯。

## 操作流程

1. 輸入密碼解鎖後，**首先**看到「選擇要填寫的表」選單：**適性總表** 或 **適性紀錄(家長版)**
2. 選定表別後，進入**幼兒列表**（與適性總表共用同一份幼兒名單，不分開維護）
3. 點選幼兒 → 進入該幼兒在「該表別」之下的清單（適性紀錄清單頁樣式比照適性總表清單頁：可新增、可刪除，依階段＋紀錄年月排序）
4. 新增一份適性紀錄時，一樣依「今天日期－出生日期」自動預選階段，可手動覆蓋；並選擇紀錄年月
5. 進入單一份適性紀錄後，用**分頁籤**呈現四大區塊：**課程計畫表｜適性發展紀錄表｜行為觀察｜點滴分享**（不做成一次捲到底的單頁，降低選擇項目多、照片多時的視覺負擔；分頁籤讓老師方便在「適性發展紀錄表」撰寫時回頭查看「課程計畫表」已填寫的項目）
6. 所有輸入即時自動儲存，不需手動按「儲存」

## 資料模型

**ParentReport（適性紀錄）**
- id
- childId（所屬幼兒，沿用既有 Child）
- tier（月齡階段，Ⅰ~Ⅴ，邏輯同適性總表：自動預選＋可手動覆蓋）
- period（紀錄年月，如「115年06月」）
- createdAt

**CoursePlanEntry（課程計畫表：指標＋活動）**
- id
- reportId
- indicatorCode（指標代碼，如 Ⅴ-1-6，來源同既有 IndicatorReference）
- activityName（老師自訂活動名稱，如「我愛畫畫」，對應範例中的【活動名稱】）

同一個指標代碼可以有多筆不同 activityName 的 CoursePlanEntry（老師本月可能用不同活動教同一個指標），由老師自由新增，不預留固定筆數。

**CourseOccurrence（課程計畫表：每一筆實施紀錄）**
- id
- entryId（所屬 CoursePlanEntry）
- date（課程實施日期）
- status（`developed` 已發展○ ／ `developing` 發展中△）
- absent（布林值，true 表示請假／未執行，匯出時該筆的日期＋說明整列加上刪除線樣式）
- note（說明文字）

一個 CoursePlanEntry 下可有多筆 CourseOccurrence，由老師自由新增。

**DevelopmentRecordEntry（適性發展紀錄表：段落）**
- id
- reportId
- domain（發展領域 1~5）
- courseEntryIds（陣列，引用該領域內、課程計畫表已填寫的 CoursePlanEntry id，供匯出時列出對應的指標＋活動）
- narrative（老師自行輸入的敘述文字）

同一領域可有多筆 DevelopmentRecordEntry（老師自由新增段落），每筆可勾選多個已填寫的課程計畫表項目。

**BehaviorObservationEntry（行為觀察）**
- id
- reportId
- title（老師自訂標題，如「我會好好說！」）
- narrative（敘述文字）

不綁定任何指標，可自由新增多筆。

**HighlightEntry（點滴分享）**
- id
- reportId
- photos（1~3 張，每張存為壓縮後的 Blob）
- caption（一組照片對應一個描述欄位）

可自由新增多組，每組 1~3 張皆可（不強制滿 3 張，匯出時空位留白）。

## 課程計畫表 — 欄位與狀態

表格欄位：發展領域｜指標｜活動名稱/能力指標｜課程實施日期【已發展○】【發展中△】｜說明。

- 發展領域欄依領域分組合併儲存格（同一領域的多個指標＋活動共用一格），並依範例文件的儲存格網底顏色上色（顏色直接取自範例 docx 的儲存格網底設定，實作時用程式讀取 OOXML 網底色碼，不自行另訂配色）
- 指標／活動名稱欄依「同一個 CoursePlanEntry 底下的多筆 CourseOccurrence」合併儲存格
- 每筆 CourseOccurrence 各佔一列：日期欄顯示「MM/DD」＋狀態符號（已發展＝○，發展中＝△）；`absent = true` 時，日期欄與說明欄文字加上刪除線樣式，不顯示○/△符號（對應範例中「請假」的劃掉表現）

## 適性發展紀錄表 — 欄位與呈現

依領域分區塊（只顯示該份報表實際有填寫段落的領域，沒有內容的領域不出現）：

- 領域標題列：領域色塊＋置中領域名稱（顏色與課程計畫表的領域色一致）
- 底下列出該段落引用的「指標代碼＋活動名稱」清單（每項一行）
- 接著是老師輸入的敘述段落（首行縮排，比照範例的排版方式）
- 同一領域可有多筆段落，依新增順序排列

## 行為觀察 — 欄位與呈現

標題列（「行為觀察－{老師自訂標題}」）＋敘述段落，可有多筆，依新增順序排列。

## 點滴分享 — 欄位與呈現

- 標題列「點滴分享」（色塊，同範例）
- 每組：1~3 張等寬照片並排（缺少的欄位留白）＋底下一列置中描述文字
- 可有多組，隨內容自動跨頁延續（不特別限制每頁組數，交給 Word 分頁自然處理）
- 上傳時前端用 Canvas 自動壓縮／縮小尺寸（如最長邊 1600px、降低畫質），減少 IndexedDB 佔用空間與備份檔大小

## Word 匯出

- 沿用適性總表已驗證過的頁首圖示、字型、邊界設定
- 依上述四區塊＋家長回饋／簽名欄（簽名欄留空白，同適性總表作法，供列印後手寫）產生 .docx
- 開發完成後，比照適性總表的驗收方式：用 Word 實際開啟匯出檔、轉存 PDF、逐頁截圖，跟填寫完成的 PDF 範例樣本逐項比對表格結構、合併儲存格、刪除線、顏色、字型，確認一致才算完成

## 舊檔 Word 匯入

沿用適性總表既有的「先解析、預覽、老師確認後才存檔」機制，絕不在解析失敗或有疑慮時直接覆蓋資料：

- 課程計畫表／適性發展紀錄表／行為觀察三個文字區塊：解析邏輯比照既有 C表 匯入（讀取 `<w:tr>`/`<w:tc>`/`<w:t>`、追蹤 vMerge 延續儲存格）
- 點滴分享的照片：從舊 docx 的 `word/media/` 依序取出內嵌圖片，依表格內出現順序對應到每一組的照片欄位；由於舊檔的圖片與說明文字對應關係不一定穩定，預覽畫面會把解析出的照片縮圖與說明文字並排列出，讓老師逐項檢查後才確認匯入，任何一組都可以在確認前手動移除或調整

## 儲存與備份

- 照片以 Blob 格式存在 IndexedDB（上傳時已壓縮）
- 「匯出備份」JSON 時，照片轉成 base64 字串內嵌；「匯入備份」時反向還原成 Blob。備份檔案會因此變大，這是已知取捨
- 刪除一份適性紀錄時，一併清除底下所有 CoursePlanEntry／CourseOccurrence／DevelopmentRecordEntry／BehaviorObservationEntry／HighlightEntry（含照片）
- 幼兒列表若刪除某幼兒，也要一併清除該幼兒名下的適性紀錄與所有子資料（不只是既有的適性總表）

## 非目標（本階段不做）

- 適性紀錄與適性總表之間互相帶入資料（如自動帶入已達成指標候選清單）——先各自獨立填寫，未來有需要再議
- 多人協作／雲端同步
- 家長端的線上檢視或簽名功能（家長回饋／簽名欄仍是留白供列印後手寫）

## 驗收方式

- 以「陳小安」為測試幼兒，比照範例文件內容建立一份完整的適性紀錄（課程計畫表＋適性發展紀錄表＋行為觀察＋點滴分享皆有內容），匯出後與 PDF 範例逐頁比對表格結構、劃線、顏色、字型
- 確認點滴分享 1、2、3 張照片皆能正常儲存與匯出排版，缺少的欄位留白不跑版
- 確認課程實施日期標記「請假／劃掉」時，匯出檔正確顯示刪除線且不顯示○/△符號
- 確認舊檔匯入的預覽機制：解析失敗時停在預覽頁不誤存資料；正常解析時老師可在預覽階段調整後才確認存檔
- 確認新增／刪除適性紀錄功能正常，刪除會連帶清除所有子資料與照片
- 確認備份匯出／匯入後，含照片在內的所有資料完整不遺失
